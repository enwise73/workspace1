## 1\. 배경 및 문제 정의

### 1.1 현재 통근 동선

\[집\] \--도보--\> \[운정중앙역\] \--GTX-A(약 22분)--\> \[서울역\]

     \--도보/환승--\> \[서울역 버스정류장\] \--버스--\> \[명동\] \--도보--\> \[교원빌딩\]

- GTX-A 운정중앙\~서울역 구간은 2024.12.28 개통, **표정 소요시간 약 22분**, 출퇴근 시간대 **배차 6분 15초**, 평시 배차는 더 김.  
- 서울역\~명동 구간은 버스 이용. 버스는 정시성이 낮고 배차·도로상황 편차가 큼.

### 1.2 문제

1. **구간이 3개(도보-철도-버스)로 쪼개져 있어 "지금 나가야 하나?"를 한 화면에서 판단할 수 없다.** 지도 앱은 "지금 출발 기준 경로"는 주지만, "목표 도착시각을 맞추려면 몇 시에 집을 나서야 하는가"를 매일 역산해주지 않는다.  
2. **환승 대기 손실이 크다.** GTX를 1대 놓치면 6~~15분, 서울역에서 버스를 놓치면 5~~10분이 그대로 손실된다.  
3. **지연·이상 상황을 출발 전에 알 수 없다.**  
4. **아침 준비 판단이 흩어져 있다.** 오늘 기온이 몇 도인지, 우산을 챙겨야 하는지, 미세먼지 때문에 마스크가 필요한지를 알려면 날씨 앱을 또 열어야 한다. 옷을 다 입고 나서 비 예보를 확인하는 순서 역전이 잦다.  
5. **주말·공휴일에도 알림이 오면 앱을 꺼버리게 된다.** 알림형 도구는 "필요 없는 날 조용한 것"이 신뢰의 전제다.

### 1.3 해결 가설

> **영업일 아침에만**, 오늘의 날짜·요일·날씨·기온·준비물과 함께, 각 구간의 실시간 데이터로 역산한 **"지금 나가라 / N분 뒤 나가라 / 이미 늦었다"** 라는 결론을 **하나의 메시지와 하나의 화면**으로 밀어주면, 아침의 판단 비용과 대기 손실이 함께 사라진다.

> 07:05, 텔레그램 메시지 1건.

> 📅 9월 14일 (월) · 이번 주 1번째 영업일

> 🌡 현재 18°C / 최저 15 · 최고 24 · 체감 17

> ☔ 오전 강수확률 70% — 우산 챙기세요

> 😷 미세먼지 '나쁨' — 마스크 권장

> 👕 얇은 니트 또는 가디건 (퇴근 18시 13°C)

> ─────────────

> 🚶 07:38 출발 (07:35\~07:41)

> 🚄 07:52 GTX-A → 08:14 서울역

> 🚌 08:22 405번 → 08:34 명동

> 🏢 08:38 도착 (목표 08:50 · 여유 12분)

**S0-1. 비영업일**

> 토요일 07:05. **아무 알림도 오지 않는다.** 앱에 들어가면 "오늘은 영업일이 아닙니다 · 다음 영업일 9/14(월)"만 표시된다.

**S1. 문 앞에서 확인**

> 나가기 직전 홈 아이콘을 누르면 큰 글씨로 **"지금 출발"** 또는 **"4분 뒤 출발"**. 그 위에 오늘 날짜·요일·기온이 한 줄로 붙어 있다.

**S2. 지연 감지**

> 07:25, "⚠️ GTX-A 상행 지연 추정 \+6분. 07:32 출발 권장 또는 경의중앙선 대안."

**S3. 휴가 등록**

> 설정에서 9/18을 '휴가'로 등록해두면, 그날 아침엔 알림이 오지 않는다.

**S4. 퇴근 (v1.1)**

> 17:40, "지금 나가면 명동 17:48 버스 → 서울역 → 18:05 GTX → 18:32 운정중앙 도착. 밤 기온 12°C, 겉옷 챙기세요."

**S5. 회고 (v2)**

> 금요일 저녁, "이번 주 평균 문전 소요 62분. 07:35\~07:40 출발이 가장 빨랐음(평균 58분)."

## 4\. 핵심 개념

### 4.1 운영 규칙 — **영업일 게이트 (Business-Day Gate)**

> **모든 능동 동작(알림 발송, 스케줄 실행, 폴링)은 "오늘이 영업일"일 때만 수행한다.** 이것은 기능(feature)이 아니라 시스템 전역의 **선행 조건**이다. 브리핑·리마인더·지연감지 워크플로는 실행 즉시 이 게이트를 먼저 통과해야 한다.

**영업일 판정 순서** (앞의 조건이 우선):

| 순위 | 조건 | 결과 |
| :---- | :---- | :---- |
| 1 | 사용자가 **수동 지정**한 날짜 (휴가 / 재택 / 임시휴무 / 특별근무) | 지정값 그대로 적용 (수동이 항상 최우선) |
| 2 | 토·일요일 | 비영업일 |
| 3 | **법정공휴일** (특일 정보 API, 대체공휴일·임시공휴일 포함) | 비영업일 |
| 4 | 그 외 | **영업일** |

- **재택근무일**은 "영업일이지만 통근 없음"으로 별도 상태 → 교통 판정은 생략하고 날씨 브리핑만 발송(설정으로 on/off).  
- 수동 모드: 설정에서 `오늘 쉬기 / 오늘 근무` 원탭 토글 제공 (임시공휴일 API 미반영, 갑작스런 연차 등 대응). 당일 자정 자동 해제.  
- **비영업일에도 수동으로 앱에 들어오면 교통 정보는 정상 조회된다.** 침묵의 대상은 *알림*이지 *조회*가 아니다.

### 4.2 "출발각(Departure Verdict)"

앱의 교통 계산은 **하나의 산출물**로 수렴한다.

verdict \= {

  status:  "GO" | "WAIT" | "LATE" | "IDLE" | "OFF\_DAY",

  leaveAt: "07:38",

  window:  \["07:35", "07:41"\],   // 출발 창(알림 지연 내성)

  countdown: "4분 뒤",

  plan: \[구간별 타임라인\],

  arriveAt: "08:38",

  slack: 12,                      // 목표 대비 여유(분). 음수면 지각 예상

  reasons: \["비 예보로 도보 \+3분", "GTX 07:52편 기준"\]

}

### 4.3 역산 로직 (Backward Planning)

목표 도착시각 `T_target`(예: 08:50)에서 거꾸로 계산한다.

T\_target

  └─ (-) 정류장→회사 도보           d4

  └─ (-) 버스 승차 소요             b   ← 실시간 도착정보 기반 보정

  └─ (-) 버스 대기                  w2  ← 실시간 도착정보로 특정 차량 지정

  └─ (-) 서울역 하차→버스정류장 도보  d3  (개찰/환승통로 포함)

  └─ (-) GTX 승차 소요              22분

  └─ (-) 승강장 대기                w1  ← 시간표/실시간으로 특정 열차 지정

  └─ (-) 개찰→승강장                d2

  └─ (-) 집→운정중앙역 도보          d1

  └─ (-) 날씨 보정                  Δw  ← §4.5

  \= 권장 출발시각 T\_leave

핵심은 **"평균값 합산"이 아니라 "실제 탑승 가능한 특정 편(便)을 고정"** 하는 것. `d1+d2` 이후 도착 가능한 **가장 이른 GTX 편**을 잡고, 그 도착시각 \+ `d3` 이후 탑승 가능한 **가장 이른 버스**를 잡는다. 결과가 목표 도착시각을 넘기면 한 단계 앞 GTX 편으로 당긴다.

### 4.4 여유(Buffer) 정책

| 구간 | 기본 버퍼 | 근거 |
| :---- | :---- | :---- |
| GTX 승차 | \+2분 | 개찰\~승강장 이동, 1편 놓침 방지 |
| 버스 환승 | \+3분 | 버스 도착정보 오차가 가장 큼 |
| 최종 도착 | \+5분 | 개인 안전여유(설정에서 조정) |

> 버퍼는 하드코딩하지 않고 **설정값**으로 둔다. 실측이 쌓이면(v2) 자동 보정.

### 4.5 날씨 보정 (Weather Adjustment)

날씨는 **브리핑용 정보**인 동시에 **역산의 입력 변수**다.

| 조건 | 보정 |
| :---- | :---- |
| 비(강수확률 60%↑ 또는 강수 중) | 도보 구간 \+20%, 버스 승차 \+5분 |
| 눈 / 결빙 | 도보 \+40%, 버스 \+8분 |
| 체감 \-5°C 이하 또는 33°C 이상 | 도보 \+10% |
| 강풍·호우 등 기상특보 | 경고 배너 \+ 출발 10분 앞당김 제안 |

### 6.2 아키텍처 결정 사항 및 근거

**결정 1 — 정적 PWA를 기본으로 하되, 얇은 프록시를 1개 둔다.** 한국 공공데이터 API는 대부분 CORS 헤더를 주지 않아 브라우저 직접 호출이 차단되고, 서비스 키도 노출된다. → **Cloudflare Workers 무료 플랜에 20\~30줄 프록시 1개.** "서버"가 아니라 CORS 어댑터에 가깝고 비용 0원. 프런트는 여전히 GitHub Pages 정적 파일.

**결정 2 — 알림은 텔레그램 봇 \+ GitHub Actions cron.** 웹푸시는 iOS 제약과 구독 관리가 번거롭다. 텔레그램은 토큰·chat\_id 각 1개로 끝난다. ⚠️ GitHub Actions `schedule`은 정시 보장이 없고 혼잡 시 수 분\~15분 지연된다. → ① 목표보다 10분 선행 실행 후 내부 대기, ② 알림을 **"출발 창(window)"** 형태로 표현해 지연 내성을 준다.

**결정 3 — 계산 로직은 브라우저와 Actions가 공유한다.** `planner.js` / `businessday.js` / `weather.js`를 ES 모듈로 작성해 PWA와 Node(Actions) 양쪽에서 import. 화면과 알림이 서로 다른 값을 말하는 버그를 원천 차단.

**결정 4 — 데이터 신선도에 따라 조달 경로를 나눈다.**

| 데이터 | 신선도 요구 | 조달 |
| :---- | :---- | :---- |
| 버스 도착정보 | 초 단위 | 실시간 프록시 호출 |
| GTX 시간표 | 개정 시 | 저장소 정적 JSON |
| 기상 실황/예보 | 10분\~1시간 | 프록시 \+ 캐시 |
| 공휴일 | 연 단위 | **Actions가 월 1회 받아 `holidays.json` 커밋** (런타임 의존 제거) |

| R4 | **Actions 러너가 UTC** | 07:05 알림이 엉뚱한 시각에 발송 | cron을 UTC로 환산(예: `5 22 * * 0-4`), 코드 내부는 `Asia/Seoul` 강제 |
| R5 | **임시공휴일 API 반영 지연** | 쉬는 날 알림 발송 | `오늘 쉬기` 원탭 토글 \+ 수동 예외일이 API보다 우선 |
| R6 | 기상청 격자좌표(nx, ny) 오지정 | 엉뚱한 지역 날씨 | P0에서 운정·명동 좌표 실측 검증 |
| R7 | 기상 API 발표 주기 지연 | 브리핑 시 예보 공백 | 직전 발표 회차로 폴백, "07:00 발표 기준" 명시 |
| R8 | API 서비스 키 노출 | 쿼터 소진 | 프록시에만 키 보관 \+ Origin 화이트리스트 |
| R9 | 저장소 public 노출 | 집 위치·휴가 일정 유추 | 좌표·정류장 ID·예외일을 코드에 하드코딩하지 않고 localStorage로만 관리, 기본값은 더미 |
| R10 | 버스 도착정보 오차 | 버스 놓침 | 버스 버퍼 3분, "다음 차량"까지 병기 |
| R11 | 도보 시간 개인 편차 | 오차 누적 | 초기 수동 설정, v2 자동 보정 |
| R12 | **브리핑 정보 과잉** | 메시지가 길어져 안 읽힘 | 조건부 노출 원칙 — 비 안 오면 우산 줄 생략, 미세먼지 '보통' 이하면 생략 |

## 14\. 오픈 이슈 (결정 필요)

3. 명동 교원빌딩 **최인접 정류장 및 실제 이용 노선 번호**.

6. GitHub 저장소 **public / private**.  
7. GTX 지연 시 실제 **대안 경로**(경의중앙선 운정역? 광역버스?).

10. **브리핑 발송 시각** — 07:05이 적절한지(기상 직후 vs 출발 30분 전).  
11. 옷차림 기준을 **기상청 체감온도**로 할지 **실제 기온**으로 할지 (개인 체감 편차).
